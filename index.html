Jarvis

Modular voice AI assistant

Python, Flask, Cohere, Groq (Llama 3.1), DuckDuckGo Search, SpeechRecognition, pyttsx3 Source on GitHub

A desktop voice assistant built around a semantic router. A Cohere model classifies each transcribed request as a general question, a real-time question or a system command, and each type follows its own execution path instead of going through one monolithic prompt.

Real-time questions pass through a second router that chooses between the Wikipedia API and DuckDuckGo search, and the retrieved context is injected into Llama 3.1 on Groq, so answers rest on fetched data rather than model memory. System commands skip the LLM entirely and resolve against an explicit allowlist of OS actions, so a model response can never execute an arbitrary command on the host.

Text-to-speech runs in a separate subprocess that can be killed the moment a new request starts, so playback never blocks the next question. A Flask backend with CORS serves the browser frontend.

TerminalChat

Encrypted terminal chat system

Java, TCP sockets, multithreading, JDBC, MySQL, RSA/AES Source on GitHub

A chat server written directly on Java sockets with a thread-per-client model. Every connection gets its own handler thread and registers in a shared map, which lets the server route a message to one specific recipient instead of broadcasting it to everyone.

The server runs in two modes, one-to-one messaging and group rooms, on top of a MySQL-backed login where all database access goes through parameterised prepared statements. It is designed for hybrid encryption: RSA public keys exchanged between clients for direct messages, and an AES key per group room. I wrote the specification, the data model and a dated engineering log before writing any code.

Event Booking System

REST API for ticketing

Java 21, Spring Boot 3, Spring Security, Spring Data JPA, MySQL, Maven Source on GitHub

A ticketing backend with the API split into separate public and admin controllers, so administrative operations sit behind their own authorization boundary.

Authentication runs through Spring Security with a custom UserDetailsService that maps database records onto security principals. The domain is modelled across users, events, tickets and payments, each with its own repository and service layer, and confirmation emails go out through Spring Mail.
